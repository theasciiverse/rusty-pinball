# Original parity audit: tables 3 and 6

> **Provenance and status.** Detailed notes from the original-parity audit of 2026-10-02, written by a research
> agent that read the original Java source and grepped our Rust source. Line numbers are into the code as it was
> when the audit ran (commit `fa27092` on branch `rapier-0.36`) and will drift. The master document,
> [../ORIGINAL-PARITY.md](../ORIGINAL-PARITY.md), is the authoritative summary; it records which claims below were
> verified, corrected or since fixed. Where this file disagrees with the master document, the master wins.
>
> **Corrections and fixes since this was written**
> - Table 3's four drop banks had no targets (generated from `wallStart`); FIXED in commit `b6f264b`, so row 3.7, 3.8 and 3.14 now see real banks.
> - Verified by hand: table 3's three bumpers have score 0 in the JSON (the script awards 500 plus bonus); Rust rollover groups add the group score again on completion, which the original does not.
> - Launch barrier (rows 3.16, 6.14) and saver restore by bank (3.14, 6.15) are implemented.
>

Original paths: delegates in `.../vectorpinball/fields/Field3Delegate.java` (F3) and `Field6Delegate.java` (F6); JSON in `app/src/main/assets/tables/`. Rust paths are under `asciiverse/games/rusty-pinball/src` (`physics/mod.rs` = PW, `physics/movers.rs`, `game.rs`, `ui/dmd.rs`, `renderer/mod.rs`).

Global facts verified in the Rust port (relevant to every row below):
- No delegate logic exists for Field3Delegate or Field6Delegate. `delegate` is only inspected in `movers.rs` (Field2Delegate rotating bumpers, Field5Delegate rotating triangle). Everything below that is delegate behavior is therefore MISSING unless noted.
- The physics world holds a single ball (`ball_handle: Option<RigidBodyHandle>`, PW:420). There is no ball list, no `launch_ball` while another ball is in play, no multi-ball drain logic (app.rs:270-275 parks the one ball).
- The only sensors recognised by id are `LaunchBarrierSensor`/`LaunchBarrierRetract` (PW:573-578). Sensors with `ballLayer` become layer sensors (PW:579). Any other sensor id (loop detectors, orbit detectors) is dropped. No per-ball "most recent sensor id".
- No game message / toast system (grep of `ui/dmd.rs`, `app.rs`, `game.rs`: none). No scheduled-action facility. Only a `PhysicsSound::BumperHit` sound exists (audio/mod.rs).
- Score multiplier is an integer 1 to MAX with `apply_multiplier_delta` (game.rs:92); the only source is a rollover group with JSON `multiplierStep` (PW:1383). Only `table9.json` sets it. Tables 3 and 6 FlipperRollovers have no `multiplierStep`.
- Per-element colour is static (parsed once at build). No runtime `setNewColor`, no `setRetracted` API except launch barrier and ball savers (restore only), and no `setAllRolloversActivated` from code.
- Rollover scoring divergence (affects both tables): original awards only the per-rollover score on activation (RolloverGroupElement.java:208-228; the group `score` is just the default for each rollover). Rust awards `rv.score` or the group score on activation (PW:1363) AND adds the group score again on group completion (PW:1380-1382), and auto-resets after a flash (PW:1377-1390). Original has no automatic group reset; it uses per-rollover `reset` seconds timer (RolloverGroupElement.java:215-217) or the delegate calls `setAllRolloversActivated(false)`.
- Table 6 JSON: Rust `table6.json` equals original except `ballradius` 0.46 in Rust vs 0.5 in original. Table 3 JSON is identical.

### Dependencies summary
- Delegate hook layer (per-table callbacks: gameStarted, ballLost, tick, bumper hit with dynamic score, drop-bank completed by id, rollover group completed by id).
- Multi-ball support (ball list, launch while another is in play, balls <= 1 detection, drain of one ball not ending ball) for 3.10, 3.11, 3.12.
- Scheduled actions (delayed `launchBall` at 1000 and 3500 ms) for 3.10.
- Game messages (toast with duration): multiball, save enabled, multiplier.
- Runtime element colour changes (`setNewColor` for rollover groups, bumper main and outer colour with alpha 128), plus temperature palette.
- `setAllRolloversActivated` / programmatic rollover state and the original rollover scoring semantics (per-rollover score, no auto-reset, timed `reset`).
- Fractional/incrementing multiplier: integer is fine for table 3 (`incrementAndDisplayScoreMultiplier`), just needs `multiplierStep` data or delegate.
- Dynamic bumper scoring with score animation (bumper JSON score 0 means these bumpers currently give nothing).

### Dependencies summary
- Multi-ball support (ball list, extra launches, `balls <= 1` check) for 6.9, 6.10, 6.11.
- Per-ball state: primary and secondary colours (set on planet contact; read by renderer and by `activatePlanetIfMatch`) and "most recent sensor id" per ball.
- Sensors by id with enter events delivered to a delegate (loop/orbit detectors, launch sensors) for 6.7 and 6.8.
- Movable rollover circles (centre updated each tick), plus runtime rollover colour per index and a colour blend helper, for 6.1, 6.3.
- Delegate tick that runs when no ball is in play (`isFieldActive` true) and knows game-in-progress.
- Per-ball gravity/impulse force hook (point attractors with 1/(depth^2 + d^2) falloff) for 6.12.
- Scheduled actions (+1000 and +4000 ms launches).
- Game messages with durations (multiball, jackpot with multiplier, planet activated, ramp bonus, save enabled, multiplier).
- Score animation at a world position.
- Programmatic rollover state (`setAllRolloversActivated`) and original rollover scoring/reset semantics.
- Callbacks by element id: drop bank completed, rollover group activated (planet groups, Planet2Rollovers, FlipperRollovers).
- Fractional multiplier is not needed (integer `incrementAndDisplayScoreMultiplier`), only the `multiplierStep` data or delegate hook.
- No extra-ball award is used by either table.
