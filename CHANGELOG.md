# Changelog

All notable changes to Rusty Pinball are documented here.

## [Unreleased]

### Added
- Moving table elements, starting with table 2 (Round and Round): its two groups of orbiting bumpers now orbit, ported from the original's `Field2Delegate`. Four bumpers circle the center bumper at 0.75 rad/s and two circle (9.35, 13) at -0.5 rad/s, in sim time like everything else, with their physics bodies following the drawn positions so the ball hits them where they are. New `src/physics/movers.rs` holds the motion code; tables now parse the JSON `variables` block that the original's delegates read. Bumpers are moved to their first-frame positions at load so nothing jumps on frame one
- Left and right Shift also work the flippers, on terminals that support the Kitty keyboard protocol (the game now requests all-keys reporting, and the menu and in-game Esc/Q ignore key-release events so that doesn't double-fire or quit on a Q release)
- Table 9, **Party Land**: an original table (not a Vector-Pinball port) recreating David's first pinball table, Party Land from Digital Illusions CE's *Pinball Fantasies* (1992), from an archived rule sheet — no schematic survives, so geometry is hand-designed to match the described shot layout. Built entirely from existing element types (walls, bumpers, flippers, drop targets, rollover groups) with no new physics; the four true "ball vanishes into a hole" captures (Left Sinkhole, Tunnel, Arcade, Hidden Entrance) are approximated as scoring kick-walls at the same spot rather than true capture/eject physics. Tunnel/Arcade/Hidden-Entrance each get a funnel mouth (matching the Left-Sinkhole idiom) and Cyclone/Skyride are proper two-rail channels (matching the orbits), rather than bare floating wall stubs
- Timed super mode on Party Land: the first hit that maxes out the Ghoul Skull award ladder (once per ball) doubles the score multiplier for 15 seconds, stacking with the base multiplier from Puke Rollovers (so a maxed-out base ×5 becomes ×10 during the mode). The last of the five originally-deferred Party Land features. New optional per-bumper `triggersSuperMode` JSON field (`BumperDef`), only meaningful alongside `awardLadder`. `GameState` gained a `super_mode_ticks` countdown (~30 Hz, matching `sync()`'s call rate) and an `effective_multiplier()` that `add_score` now uses instead of the raw multiplier; ends early if the ball drains. DMD replaces the `×N` status readout with a `SUPER 15s` countdown (counting down, bright magenta) while active — the first genuinely new piece of state (a timer) added on top of the score/sound/multiplier event-channel pattern the rest of Party Land's mechanics share
- Jackpot on Party Land: once every letter-award word (MAD, CRAZY, PARTY) has been completed at least once since the ball started, the Jackpot lights at Ghoul Skull; the next hit there collects 100 000 pts and un-lights it. Built first, ahead of timed super-modes, since it's the smaller piece and the natural building block for one (most "super mode" implementations are just a timer wrapped around a lit jackpot shot). New optional table-level `jackpot` JSON field (`{ shot, score }`) requiring `letterAwards` to be non-empty to ever light; reached through the same `shot_id`/`record_shot` dispatch already built for letter-lighting, which now also returns the jackpot's payout when the hit shot happens to be the lit jackpot shot. Resets (un-lit, completion progress cleared) on every new ball
- Bonus multiplier on Party Land: completing the Puke Rollovers group (all four lit) raises the score multiplier by ×1, on top of its existing completion bonus, capped at ×5; resets to ×1 on every new ball. `GameState` already had a `multiplier` field wired into scoring but nothing had ever changed it from ×1 before this. New optional per-rollover-group `multiplierStep` JSON field (`RolloverGroupDef`); the other rollover groups on every table are unaffected. Multiplier changes reach `GameState` via a new `drain_multiplier_events()` channel, the same pattern as the existing score/sound event channels
- Ghoul Skull award ladder on Party Land: each hit awards the next rung of an escalating value (5 000 / 10 000 / 20 000 / 35 000 / 50 000), then holds at the top for the rest of the ball; resets to the first rung on every new ball. New optional per-bumper `awardLadder` JSON field (`BumperDef`) — when present it takes over from the flat `score` field for that bumper; every other bumper on every table is unaffected. DMD shows the currently-armed value ("AWARD  5,000") for any table that has one
- Letter-lighting on Party Land: hitting any of a word's shots lights that letter (any order); completing MAD, CRAZY, or PARTY flashes the DMD and awards a bonus (10 000 / 20 000 / 30 000 pts), then resets so it can be spelled again. An Asciiverse-original design — not from the real Party Land's ruleset, which no longer survives — that maps each letter onto an existing named shot already on the table (Ghoul Skull, Cyclone/Skyride ramps, the orbits, outlanes, Center Post, and the four capture kick-walls) rather than adding new targets. New optional `letterAwards` table-JSON field (`word` + ordered `shots` list of element `id`s + `score`), parsed only for table 9 — the other 8 tables are unaffected. Shot identity is tracked via a new `shot_id` field alongside each bumper/kick-wall/drop-target-group/rollover-group/spinner's existing debug label
- Per-element JSON colors (`color`/`outerColor`/`ballcolor`) are now rendered instead of being silently dropped — bumpers, the ball, rollovers, drop targets, and plain (non-layered) walls all show their table-specified colors; tables that never set unusual colors render identically to before
- Spinners (`SpinnerElement`): virtual, non-colliding zones — a ball crossing one at or above `minActivationSpeed` sets it spinning, flashing on/off at a decaying frequency and scoring once per cycle until the frequency decays below `minCyclesPerSecond` and it goes idle; ported from Vector Pinball's tick-based model (table 8's `LeftOrbitSpinner`)
- Debug object-ID overlay (`I` key while playing): labels every wall segment, kick-wall, drop target, bumper, flipper, rollover, and spinner with its index in the table JSON's `elements` array (`N` for single elements, `N.i` for grouped sub-items like rollovers/drop targets), for cross-referencing mechanics against the source table. Labels now also show the element's `id` when the table names it (e.g. `23:BallSaver-left` instead of just `23`) — `BumperDef`/`FlipperDef`/`SpinnerDef`/`WallArcDef`/`WallPathDef` weren't parsing `id` at all before, so named bumpers/flippers/spinners/arcs/paths only ever showed their bare index
- Drop targets: per-target proximity hit detection, targets disable on contact, group-clear bonus (2 000 pts), groups reset when fully cleared
- Shooter-lane gate: horizontal wall across the lane that closes once the ball escapes upward, preventing it from rolling back into the dead zone
- Dead-zone detection: ball that rolls back before clearing the gate is automatically re-parked and the player can re-launch
- `park_ball()`: freezes ball at launch position with gravity off; reactivates ball-saver kick-walls for each new ball
- Drop targets rendered in yellow in the braille viewport
- `WallArcDef` now accepts `radius` (circular arc) as a fallback when `xradius`/`yradius` are absent — fixes table 2 loading
- First unit tests: regression coverage for spinner activation/scoring/decay and the table 8 load fix below (`cargo test`)

### Fixed
- Ball savers and slingshots now actually throw the ball: the kick fires on proximity, just before contact, so it only cancelled the ball's approach speed and a ball saver (which retracts at once) let the ball drop straight through. The ball is now bounced off the wall first (restitution 0.8) and then given the kick, which is what the original gets from applying the kick after the physics step has resolved the collision. Tests cover both savers and the slingshot at three approach speeds
- Flipper-cycled rollover groups on Classic (bottom and top lanes) cycle one place per flipper press again; the press edge was being applied once per physics substep. Direction now matches the original (right flipper moves the lit dots right, left moves them left, right wins if both fire at once)
- Party Land: closed a gap between the top arc and the left wall that let the ball escape the field at the top-left corner (not reachable at the old slow sim speed)
- Slingshot kick-walls (and ball-savers, which share the same detection code) mostly didn't kick at all — the ball would just bounce off like a plain wall, only occasionally getting a kick. Hit detection relied on Rapier's `CollisionEvent::Started`, which reliably fires on a square, fairly hard hit but frequently never arrives at all for a shallow/glancing touch — and a slingshot is almost always brushed at a glancing angle as the ball rolls past, not hit head-on. Confirmed empirically with a controlled test: perpendicular hits fired 8/8 across a range of speeds, but glancing hits at low-to-moderate speed fired 0/8. Kick-walls now use the same per-step proximity check already used successfully for bumpers and drop targets (`point_to_segment_dist` against the ball, every physics step) instead of discrete collision events, which can't miss a graze the same way; the margin also had to widen slightly (`KICK_WALL_TOUCH_MARGIN = 0.10`) since the wall's own half-thickness (0.05) was silently eating the entirety of the old `ball_radius + 0.05` check, leaving zero real slack for a ball that settles a hair short of exact geometric contact. The now-unused Rapier collision-event channel (`ChannelEventCollector`, `kick_evt_send`/`recv`, the force-event channel kept alive only to avoid a disconnected-channel error) is removed entirely
- Flippers went permanently unresponsive after sitting idle for a few seconds (no ball nearby). Rapier puts still, low-velocity dynamic bodies to sleep to save CPU — the flipper resting at its limit is exactly that state — and changing a sleeping body's joint motor target does *not* wake it back up on its own, so the first idle gap of a game would silently kill flipper input for good. `add_flipper` now sets `can_sleep(false)` on the flipper body; there are only ever a couple of them, so never letting them sleep costs nothing
- Left flipper wouldn't move (right moved sluggishly) right after the dynamic-flipper rewrite below. `InputState.left_flipper`/`right_flipper` aren't a stable "held" boolean — they're a decaying counter that terminal key-repeat events keep refreshing, so the flag can flicker false for a tick between repeats even while the key is physically held. The motorized joint's target was only being updated on a state *change*, so every flicker looked like a real press/release and the motor kept getting told to reverse direction faster than it could move. Now the target is set unconditionally every tick from the current input state (as the old kinematic code did), immune to the flicker
- Table 8 (Pool Party) failed to load entirely: its JSON uses `layer: -1` on a few purely-decorative, ball-ignoring elements (a Vector-Pinball convention for a physics world no ball ever occupies), but `layer` was typed as `u8`. Negative layers now map to an unreachable sentinel layer, so those elements build without colliding or rendering — matching their original decorative-only behavior — instead of failing to parse

### Changed
- Contact model matches the original Box2D setup: ball and bumper restitution 0.6 (was 0.8), ball and bumper friction 0.3 (was 0, so the ball never gripped or rolled), walls, arcs, paths, drop targets and flippers restitution 0 with friction about 0.2 (was 0.5 to 0.8, and 0). Restitution combines as max everywhere (the bumpers and flippers did not, so ball against flipper averaged to 0.4). Rapier cannot do Box2D's geometric-mean friction mix, so wall friction is 0.19, which averages with the ball's 0.3 to the same 0.245
- Physics feel now matches the original Vector Pinball: sim time runs at each table's `targetTimeRatio` (about 2.3x real time; it was parsed in the JSON but ignored, so the ball felt like it was underwater and every bumper and slingshot kick looked weak). `PhysicsWorld::step_frame` advances one rendered frame in 8 substeps (about 9.5 ms of sim time each, like the original's 4 iterations per frame), with 10 solver iterations (Box2D's velocity iteration count). Tick-counted timers (bumper flash/debounce, slingshot debounce, rollover and letter flashes) are rescaled so they keep their real-time length. The earlier hand compensation is undone, restoring the original values on tables 1 to 8: gravity (was 1.5x), slingshot kicks (was 1.5x) and launch velocities; ball radius tweaks on tables 6 and 7 stay. Party Land gravity goes from 6.75 to 4.5 to match. New tests pin free-fall distance to the original's formula and check every table keeps the ball in bounds at game speed
- Flippers, across all 9 tables: rewritten from a kinematic body (moves at a fixed commanded speed, immune to collision forces) to a dynamic body on a motorized Rapier revolute joint — matching Vector-Pinball's original Box2D setup (density 5.0, CCD/"bullet" enabled, `maxMotorTorque`-equivalent torque cap). The ball's own momentum now genuinely affects the flipper instead of it being an unstoppable puppet. Also restores the original's collider thickness (0.12 half-height, was 0.06 — ours was half as thick as intended) and a top-of-swing motor slowdown so a ball resting near the tip isn't launched by the final bit of travel. Found by reading Vector-Pinball's `FlipperElement.java`/`Field.java` source directly rather than guessing from gameplay feel
- Package/binary renamed from `rusty-pin` to `rusty-pinball` — the "rusti-pin" pun was short-lived; menu title art and window chrome were always "Rusty Pinball"
- `launch_ball()` reuses the existing ball body rather than destroying and recreating it each launch
- Launch jitter: ±4 % Y-velocity variation plus a small lateral nudge, seeded from nanosecond wall-clock time (LCG)
- `is_ball_drained()` now ignores a ball sitting in the shooter-lane dead zone
- Active kick-walls only are included in `FieldSnapshot`; inactive (retracted) walls are hidden from the renderer
- Version bumped to 0.2.0

## [0.1.1] — 2026-06-06

### Added
- Proximity-based slingshot impulse: `WallElement` entries with a `kick` JSON field fire an impulse when the ball comes within range, with a debounce timer to prevent double-firing
- `retract_when_hit` kick-walls (ball-savers): deactivate permanently on first contact
- CCD (continuous collision detection) on the ball body to prevent tunnelling through thin walls
- Colored braille renderer (`ColoredFrame`): walls gray, kick-walls green, bumpers blue / lit yellow, flippers cyan, ball white, background dark gray
- UI groups same-color braille characters into `Span`s for per-character color output; menu items padded to equal width and centered as a block
- Flipper hold-tick decay: flippers stay raised for a few frames after the last key event, bridging the key-release gap on terminals without Kitty keyboard protocol
- Kitty keyboard protocol push/pop for accurate key-release detection where supported
- `Q` as an alternate in-game quit key
- Sound toggle actually pauses/resumes background music via `AudioManager::set_enabled()`

## [0.1.0] — 2026-06-06

### Added
- Initial release: Rust TUI pinball with Rapier2d physics and braille vector graphics
- Ball physics at 1× real time (2 steps/frame, dt = 1/60 s, 30 fps target)
- Flippers: Z / Left = left, X / Right = right; pivot positions and angles match Vector-Pinball table 1
- Bumpers with scoring (500 / 500 / 500 / 1 000 pts) and lit-flash animation
- Camera scrolls to follow the ball vertically
- Drain detection with BALL LOST / GAME OVER screens
- Full game loop: launch → play → BALL LOST → Enter to continue → GAME OVER
- DMD overlay shows score, balls remaining, and game phase
- Start menu with table selection (8 tables) and sound toggle
- 8 tables loaded from Vector-Pinball JSON assets (`assets/tables/table1–8.json`)
- Background music and sound effects via `rodio` / `kira`
